UniFi Protect Setup

Creates and configures one UniFi Protect Camera driver per camera, so the console address and API key are entered once.

Before you start

Load unifi_protect_camera.c4z into Composer first. This driver creates camera drivers with C4:AddDevice, which can only instantiate a driver already in Composer's driver database. You do not need to add a camera driver to the project yourself.

Setup

  1. Add this driver to the room where you want the cameras to appear.
  2. Enter NVR Address and API Key, then run Test Connection.
  3. Choose Snapshots On or Off.
  4. Leave Enable RTSP in Protect on Yes unless you want to manage RTSP yourself. RTSP is off by default in Protect; with Yes, each camera switches it on if needed.
  5. Run Create / Update Cameras.

One camera driver appears per Protect camera, named after it, already configured with the address, key, camera, stream tokens and snapshot setting. Move them to other rooms as you like.

What it does and does not do

This driver is only involved in setup. It is not in the video path or the event path, and each camera driver runs independently once configured. Removing this driver leaves every camera working.

Actions

ActionWhat it does
Test ConnectionChecks the address and key, reports the Protect version.
Create / Update CamerasAdds a driver for every camera without one and pushes settings to all. Safe to run any number of times.
Push Settings to CamerasSends the current address, key and snapshot setting to every managed camera. Use after rotating the API key.
Forget Managed CamerasClears this driver's list without touching any camera driver. The next Create / Update adopts them again.

Pacing

Cameras are configured one at a time, a couple of seconds apart, rather than all at once. Configuring every camera in the same instant made the console refuse requests (HTTP 429). With eight cameras, Create / Update or Push Settings takes about twenty seconds; Setup Status shows progress.

Re-running is safe

  • Cameras that already have a driver are updated, never duplicated.
  • Camera drivers added by hand, or left from an earlier install, are found and adopted rather than recreated. The driver waits a few seconds for them to identify themselves first.
  • A camera added in Protect later gets a driver on the next run.
  • Nothing is ever deleted. A camera removed from Protect keeps its driver until you remove it.

Snapshots

Each camera driver runs its own small snapshot server on an OS-assigned port, so eight cameras means eight independent listeners that cannot collide. Pushing new settings reuses each camera's existing listener, so the snapshot URL Navigators hold stays valid.

Rotating the API key

  1. Create the new key in UniFi OS.
  2. Paste it into API Key here.
  3. Run Push Settings to Cameras.

Troubleshooting

SymptomCause and fix
"Could not add a driver"unifi_protect_camera.c4z is not loaded in Composer.
Auth FailedBad or revoked API key.
A camera was duplicatedIts driver had no camera configured when it was asked to identify. Remove the duplicate.
A camera has no videoRTSP is off for it in Protect. Run Enable RTSP Streams on that camera driver.
