UniFi Protect Camera

One driver instance per camera. No hub driver — each instance talks to the UniFi OS console on its own.

Setting up several cameras? Use the UniFi Protect Setup driver instead of configuring each camera by hand. Enter the address and API key once and it creates and configures a camera driver for every Protect camera.

Requirements

  • UniFi OS console (UDM-Pro / UDM-SE / UNVR / CloudKey Gen2+) running Protect.
  • A UniFi API key with Protect access. No Protect username or password is needed.
  • Control4 OS 3.3.0 or later.

Setup

  1. Enter the NVR Address (the console's IP) and paste the API Key.
  2. Run Test Connection. Driver Status should report the Protect version.
  3. Run Discover Cameras, then choose the camera from the Camera dropdown. The stream tokens are fetched automatically.
  4. RTSP is off by default in Protect, per camera and per quality. With Enable RTSP Automatically on (the default), the driver switches it on the first time it finds no stream. Otherwise run Enable RTSP Streams.
Ports are set automatically. A new camera's proxy starts at 554, which is not Protect's port. The driver's RTSP Port property (default 7447) is the source of truth: the driver pushes it to the proxy at startup, again after a few seconds, and corrects the proxy whenever it reports a different value. To use a different port, change RTSP Port here rather than on the Camera Properties tab. If the proxy keeps reverting, Driver Status will say so.

How streaming works

The driver supplies the stream token; the camera proxy builds rtsp://<console>:7447/<token>. Plain RTSP on 7447 is used rather than RTSPS on 7441 because 7441 is SRTP behind a self-signed certificate that Control4 will not validate, while 7447 needs no certificate and no credentials — the token is the secret.

The driver declares http_tunnel, which keeps Director in the media path so streams reach remote clients through 4Sight without port forwarding.

Preferred Quality applies when a client does not state a size. Otherwise the driver picks from the requested width: up to 640 gets Low, up to 1280 gets Medium, above that High. Only qualities enabled in Protect are offered.

Snapshots

Protect refuses credentials passed in a URL, and Navigator can only fetch URLs — it cannot send headers. So the driver fetches the frame from Protect itself, with the API key as a header, caches it, and serves it from a small HTTP listener on the controller. Navigator fetches a plain LAN URL and the API key never leaves the controller. No Protect username or password is required.

Set Snapshots to On. Snapshot Status shows the listening port and whether frames are arriving. Controller Address can stay blank unless auto-detection fails.

  • The listener takes an OS-assigned port, so it cannot collide with Director or another driver.
  • Frames under 5 seconds old are served from cache; one camera makes at most one request to Protect per 5 seconds no matter how many Navigators are watching.
  • The cached frame is released after two minutes with no requests, so idle cameras hold no memory.
  • Frames are requested at standard quality. Protect re-encodes on every request and a frame from a 4K camera can still be around 1 MB, so raise the Snapshot Refresh Rate on the Camera Properties tab if several cameras are on screen at once.
  • The snapshot URL is unauthenticated and reachable by anything on your LAN. The API key is not.
  • Thumbnails may not load away from home, since the URL is a LAN address. Live video is unaffected and works remotely through 4Sight.

Events

Detection events are polled, because DriverWorks has no WebSocket client. Event Polling Interval is Off by default — no periodic API calls are made until you choose an interval.

IntervalRequests per hour, per camera
1 second3,600
5 seconds720
15 seconds240
60 seconds60

With Adaptive Polling on, any event triggers a burst of one-per-second polling for Adaptive Burst seconds before dropping back. A slow baseline then still tracks activity closely. API Call Rate shows the current figure.

Detection state clears when Protect reports the event ending; Event Hold Time is a watchdog for when no end arrives.

Programming events

Motion Detected, Motion Ended, Person Detected, Vehicle Detected, Animal Detected, Package Detected, Doorbell Pressed, Camera Online, Camera Offline.

Matching boolean variables: MOTION_DETECTED, PERSON_DETECTED, VEHICLE_DETECTED, ANIMAL_DETECTED, PACKAGE_DETECTED, DOORBELL_RING.

Troubleshooting

SymptomCause and fix
No video, Camera Test failsCheck the RTSP port on the Camera Properties tab is 7447, not 554. Reload the driver to have it set automatically.
"RTSP is off for this camera"Protect has no stream enabled and auto-enable is off, or Protect refused to enable it. Run Enable RTSP Streams.
"Protect is busy - retrying"The console asked for fewer requests (HTTP 429). The driver backs off and retries automatically; no action needed.
"Protect was too busy"Retries ran out. Wait a minute and run Fetch Stream Aliases.
"Fetching streams..." never clearsThe console is not answering. Run Test Connection.
Only one quality offeredOnly one channel has RTSP enabled. Run Enable RTSP Streams, then Fetch Stream Aliases.
Auth FailedBad or revoked API key. Run Test Connection after correcting it.
Events never fireEvent Polling Interval is Off by default.

For anything else, set Log Mode to Print and Log Level to 4 - Debug, then reproduce the problem and read the Lua tab. Debug logging disables itself after 8 hours.

Limitations

  • No audio. Protect sends AAC; Control4 accepts G.711 µ-law only.
  • No PTZ, no presets, no two-way talk, no recorded playback.
  • Detection latency matches the polling interval.
  • Smart detections fire only when Protect names a detection class. If detections arrive with no class list the driver logs a warning rather than guessing, since guessing would fire false person events.
